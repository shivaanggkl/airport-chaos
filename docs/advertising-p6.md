# P6 sponsorship measurement and moderation

**Engineering status: PASS for local P6 acceptance, 2026-10-29.** The final closure below verifies active Sky Duel suppression and hardware-accelerated performance, and corrects an exposure-episode defect found during the controlled runs. Paid serving, public measurement, external links, and public inquiry collection remain disabled in production.

## Source and implementation

Current worktree: `feature/advertising` at `95a6787e9b37de3f7a50922660f3004ee71ec957`. P0–P5 were uncommitted before P6; all changes remain uncommitted. The separate `qa` worktree was not modified. P6 adds only client sponsor measurement, server ingestion/aggregate storage, an internal CLI, focused tests, and this report. P1's 150 IDs and three approved Dallas placements, P3/P4 campaign approvals, P5 renderer/materials, gameplay, wallet, purchase, native, and inquiry logic were left intact.

Four first-party events are accepted: `HUB_ESTIMATED_EXPOSURE`, `WORLD_ESTIMATED_EXPOSURE`, `SPONSOR_DETAILS_OPEN`, and `SPONSOR_WEBSITE_ACTION`. The Hub uses `IntersectionObserver` at 50% viewport intersection, a loaded approved logo, foreground visibility, and one continuous second. Dallas reuses the existing 0.15-second placement visibility update, frustum/facing/projected-size checks, actual applied sponsored texture, and mode suppression; only the three approved signs can report. Exposure episodes need three continuous seconds out of qualifying view and a 30-second repeat separation. Details opens and website actions are emitted only after deliberate clicks; website actions also require the existing external-link gate. No event is produced for house art. Existing P4 player reports remain the moderation source of truth.

The browser holds at most 20 events, flushes about every 30 seconds or on relevant navigation, and stops after bounded failures. It creates random event IDs only, with no persistent ad identity. The server's same-origin JSON endpoint enforces an 8 KiB streamed cap, 1–20 events, strict fields/types, approved live catalog association, server time, local QA serving and measurement gates, and IP-keyed in-memory rate limiting. Accepted events are **client-reported estimates**: the server cannot independently observe the player's camera or building occlusion. A SQLite write transaction rechecks campaign eligibility before it inserts a durable 48-hour event-ID dedupe record and increments a daily UTC aggregate, or does neither; an operator pause cannot race between that check and the write. Aggregates contain campaign/immutable creative/placement/city/platform/type, with no player ID, email, IP, coordinates, or raw session. No advertiser charge or player reward uses these counts.

[Raw samples](advertising-p6-evidence/performance-raw.jsonl) contain requestAnimationFrame presentation intervals, long tasks, heap, sponsor requests/bytes, and the existing renderer overlay where available. These are **not GPU frame times**. Invalid samples lacking the game QA overlay or spanning a Hub catalog expiry were discarded and are not in the comparisons below.

| Scenario | P6 off median p95 | P6 on median p95 | Result |
| --- | ---: | ---: | --- |

| DFW near | 533.4 ms | 550.1 ms | +3.1%; software renderer ran about 2 FPS in both states |
| DFW→Canal streaming | 650.1 ms | 583.2 ms | Highly variable: individual control p95 533–950 ms |

The Hub used roughly 9–10 MiB JS heap and only catalog/event requests; no empty-queue event fetch or continuous polling occurred. Browser network transfer bytes exclude some cache activity; GPU timing and long-duration post-GC memory growth were unavailable. No new geometry, rendering pass, or per-frame network call was introduced. These initial samples were excluded from final acceptance and replaced by the accelerated comparison below.

`./node_modules/.bin/tsx server/src/sponsorship-measurement-cli.ts report <campaign-id> [from] [to] [text|json|csv]` gives campaign dates/status, assignments, daily rows, placement/city/platform breakdown, totals, report counts, and the mandatory estimate caveat. `moderation [1–100]` lists open reports without private messages; use existing `sponsorship-reports-cli` to view/review/resolve, and P3 management CLI to pause a campaign or disable creative. Text, JSON, and CSV were exercised against the isolated database. No data means **zero recorded events**, not zero actual views. Aggregate and moderation retention needs operator/legal approval; no automatic deletion was added. Only the 48-hour dedupe table is pruned.
