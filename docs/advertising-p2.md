## Inquiries and operator workflow

- Public API: `GET /api/sponsorship/inquiries` returns availability only. `POST /api/sponsorship/inquiries` accepts JSON of at most 4 KiB, enforced while streaming. It validates only six expected fields, normalized email and enum, limits, and HTTPS website hosts; rejects private IPs, local hostnames, credentials, fragments, and nonstandard ports. It requires an allowed request origin and JSON content type. The existing bounded limiter allows at most three valid submissions per trusted IP per hour; a SQLite transaction and indexed normalized email enforce one new lead per email per hour across restarts and concurrent requests. Responses contain only a generated request ID and `RECEIVED` on durable HTTP 201; failed writes return 503. No contact fields go to general logs or public list APIs.
- Records are kept in the existing SQLite profile database, in a separate `sponsorship_inquiries` table with prepared statements, UTC creation time, and `NEW`, `CONTACTED`, `CLOSED`, or `SPAM` status. No retention purge is automatic. The operator/legal owner must approve retention and deletion handling before public collection.
- Operator CLI, from the repository root: `AIRPORT_CHAOS_PROFILE_DB=/path/to/player-profiles.sqlite ./node_modules/.bin/tsx server/src/sponsorship-inquiries-cli.ts list 25`, then `view <id>` and `status <id> CONTACTED|CLOSED|SPAM`. In a built service use `node server/dist/sponsorship-inquiries-cli.js` with the same database variable. Use a restricted Render service shell and its mounted path (`/var/data/player-profiles.sqlite` in `render.yaml`, `/var/data/staging-player-profiles.sqlite` in `render.staging.yaml`); do not copy inquiry data into public logs or browser secrets. A local browser-submitted fake lead was listed, viewed, and marked `CONTACTED` through this CLI. Access to the deployed service's restricted shell and live disk was **not** exercised; public collection stays off until the operator verifies that workflow in the intended hosting environment.
- `SPONSORSHIP_PUBLIC_INQUIRIES_ENABLED` is server-owned and false unless explicitly set to `true`. The local QA server set it true for testing only. With it off, the page still displays opportunities, a disabled form and clear unavailable message, plus working `mailto:support@vadensoftware.com` and Copy Email fallback. No advertiser email delivery or automatic retry is claimed. The browser form preserves entered fields after rejection and reports success only after a confirmed 201 response.
