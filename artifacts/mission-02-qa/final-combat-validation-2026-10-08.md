# Mission 2 combat validation — 2026-10-08

Mission 2 remains **unapproved** pending genuine normal-control Day and Dusk victories.

## Isolated technical evidence

- A temporary local SQLite database and authenticated account were created and deleted during the run. Stage 1 was completed only as an isolated test fixture. No production profile was touched.
- A local server at port 18095 accepted the Stage 2 attempt over the ordinary authenticated WebSocket. Its normal DFW takeoff checks assigned one 200-HP Hunter.
- Controlled aircraft state/rotation packets followed the moving Hunter; `lock` and `fire` packets went through the server's existing lock, fire, hit and reward paths. There were no direct damage, kill or completion messages.
- Eight accepted `damage` messages for the assigned Hunter reported: **175, 150, 125, 100, 75, 50, 25, 0 HP**, each for 25 damage.
- The server's final `journeyAttempt` message was `COMPLETED`, `targetHealth: 0`, `firstClearCredits: 350`. The isolated wallet contained two `MISSION_REWARD` entries: Stage 1 250 and Stage 2 350; total 600. There was no `COMBAT_REWARD` entry for the mission target.
- The existing `journey-attempts.test.ts` replay case confirms a second Stage 2 completion returns `firstClearCredits: 0`, with only one Stage 2 wallet transaction.
- The production `sweptProjectileHit` function was evaluated against controlled moving-target trajectories. At 20 m/s lateral speed and 0.5 s travel, an unled shot missed and a led shot hit. A 100 m/s crossing trajectory was also detected between simulation samples. This checks collision geometry, not human aiming skill.
- `HUNTER_NO_FIRE NO_FORWARD_SOLUTION` is generated by the **Hunter's own** ballistic firing solution when the player or its lead point lies behind or outside the Hunter's forward cone. It is not a Bluejay shot rejection.
- One server `LOCK_SHOT_REJECT lock_geometry` appeared while the scripted controller was turning. Later locked shots succeeded. This indicates that a stale or changed shot angle can fall back to ordinary ballistic fire; it does not by itself demonstrate a client/server defect.

Run against a **local test profile** that has legitimately completed Stage 1. Do not use production data or reward shortcuts.

```bash
AIRPORT_CHAOS_DEV_QA=1 npm run dev:server
npm run dev:client
```

Open `http://localhost:5173/?combatqa=1`, sign in, choose **City Journey → Dallas → Mission Journey → Stage 2 → Play Mission → Day**. Repeat the same run with **Dusk**. The `combatqa` query enables a development-only aim/status panel; the server flag enables bounded diagnostic logs.

Use **W/S** for throttle, **Up/Down** for pitch, **A/D** or **Left/Right** to turn, **Space** to fire, and **Q/E/Z/C** for the existing manual aim offsets. Mouse drag changes the camera view; it does not steer the aircraft's weapon. Follow the gold mission marker and radar, bring the Hunter within 4.5 km, and look for **LOCKED** before firing. When the lock is absent, rounds are ballistic and must lead a moving target.

Capture a continuous recording of: runway HUD and safe takeoff; target marker/radar and lock feedback; each server-confirmed enemy HP drop; legitimate destruction; victory screen; **CONTINUE**; Stage 2 completion and Stage 3 preview. Record Credits immediately before and after the first clear, then replay and confirm no second 350-Credit award. Also test an actual crash → Retry, Hunter reacquisition, and pursuit near the Dallas airspace boundary. Keep the server's bounded `LOCK_SHOT_REJECT`, `FIRE_BLOCKED`, `HUNTER_NO_FIRE`, and transform-rejection lines with the recording; these distinguish aim, lifecycle, AI firing and boundary problems.

The isolated WebSocket controller did not use normal Bluejay flight physics or player controls. Browser automation available here can press keys but cannot reliably sustain the simultaneous throttle, pitch, turning and fire inputs required for a fair dogfight. Victory-screen rendering, Continue navigation and Stage 3 transition were traced in source but were **not** observed after a normal-control victory in this run.
